# 批量论文检索与交付

## 目录角色

本技能目录是**只读工具包**，包含：

- `SKILL.md`：本文件，工作流入口；
- `AGENTS.md`：交付契约，唯一权威；
- `scripts/new-topic.ps1`：在调用项目里建专题骨架；
- `build_index.py` / `build_delivery.py` / `export_cnki_refs.py` / `export_doi_list.py`：交付物与过程产物的生成器。

每次任务在调用项目里建独立专题：专题正文 `<项目>/<专题>/`，过程产物 `<项目>/_archive/<专题>/`。技能目录里不放专题数据、PDF、缓存或任何生成物。

## 原则

把本技能目录视为只读。多个 Agent 可并行处理不同专题；同一专题只能有一个写入者，其他 Agent 只读或分别写入命名清楚的分片，最终由一个 Agent 合并。

优先在本仓库 `preset/` 提供的 DSH「学术研究」preset 中执行检索。按可用性路由：跨库检索用 academic-search，引用图谱和标识符核验用 Semantic Scholar，开放全文用 arXiv，中文文献用 CNKI。若某项能力不可用，记录缺口并继续可验证部分；不要根据题名猜 DOI、CNKI filename、卷期页码或全文链接。

## 工作流

1. 建专题。运行 `scripts/new-topic.ps1 -ProjectRoot <项目> -Topic <专题名>`，它建立 `<项目>/<专题名>/`（含 `raw/`、`cache/`、`PDF/` 子树与检索说明骨架）和 `<项目>/_archive/`。检索说明应写清研究问题、纳入/排除条件、年份、语种、文献类型、数量目标和检索日期。
2. 拆概念组。把描述拆成 2–6 组概念，形成中英文同义词与布尔检索式；宽检索用于召回，窄检索用于补强核心方向。
3. 取候选。用当前 preset 中已安装的检索工具获取候选项，保存每批原始结果或至少保存查询、来源、时间和返回标识符，便于复跑。
4. 去重。以 DOI、arXiv ID、PMID、Semantic Scholar ID、CNKI 返回的主站 URL 为主键；无标识符时用规范化题名、年份和第一作者谨慎合并。
5. 核验。核对题名、作者、年份、来源和标识符。CNKI URL 必须来自工具返回，不得拼接；HTTP 200 证明不了 CNKI filename 有效。
6. 分级。按与主题的直接性、方法相关性、来源质量和可追溯性分级，保留排除理由，不用下载可得性替代学术相关性。
7. 取全文。只从合法开放来源或用户有权访问的来源获取，arXiv 下载保持至少 3 秒间隔并支持已存在跳过；不绕过登录、付费墙、验证码或访问控制。
8. 生成。从一个规范化条目数据源生成全部交付物，命令与顺序见 [AGENTS.md](AGENTS.md)；已有生成器可复用，先核对输入契约，不要套用历史数据。
9. 验收。打开 HTML、检查表格、核对 RIS/BibTeX 条数与下载脚本 ID，再报告结果、缺口和来源限制。

## 隔离与安全

- 不在脚本、日志、JSON 或技能说明里保存 API key、token、cookie 或账号；凭据只从当前 Agent 的安全环境或已配置连接读取。
- 不复用其他专题的可变缓存，除非缓存键包含来源、规范化查询/标识符和版本，并且复制后仍可追溯。
- 过程文件（DOI 列表、对照表、知网条目清单、crossref 缓存）统一落在 `<项目>/_archive/<专题>/`，专题目录只留交付物。
- 技能目录里的生成脚本必须显式传入专题目录；在技能目录内直接运行会写坏只读包。

## 交付

至少说明检索日期、数据源、查询范围、去重前后条数、纳入条数、全文取得情况、未核验字段和专题目录。五件套要求以 [AGENTS.md](AGENTS.md) 为准。
